# Разработка и публикация

NERKN задуман как простой интерфейс к zapret и Telegram-прокси для людей без опыта настройки сетевых инструментов. Описание проекта и условие автора об использовании собственного кода находятся в корневом [README](../README.md).

## Структура

| Путь | Назначение |
| --- | --- |
| `main.py` | Логика приложения, API pywebview, HTML/CSS/JS |
| `proxy/` | Встроенный Telegram-прокси и его лицензия |
| `bin/` | winws, WinDivert и сетевые шаблоны |
| `lists/` | Общие списки доменов и IP |
| `zapretes/` | Стратегии обхода |
| `utils/` | Вспомогательные скрипты |
| `installer_kit/` | Сборщик, спецификация и установщик |
| `tests/` | Изолированные регрессионные проверки |

Рабочий встроенный прокси находится в `proxy`. Исторические версии и результаты сборки исключены из публикуемого проекта.

## Проверки

```powershell
python tests/check_core.py
python tests/check_ui_backend.py
```

Проверки извлекают нужные функции через AST: не запускают приложение, UAC, службы, настоящий прокси или браузер. GitHub Actions выполняет их и проверяет синтаксис Python на Windows.

## Ссылки в приложении

Кнопка Telegram уже ведёт на [канал NERKN](https://t.me/nerknn). В `main.py` адреса находятся в `PROJECT_LINKS`:

```python
PROJECT_LINKS = {
    "telegram": "https://t.me/nerknn",
    "github": "https://github.com/владелец/репозиторий",
}
```

Кнопки открывают системный браузер. После создания репозитория задайте `github` HTTPS-адрес и пересоберите EXE. Пока адрес пустой, кнопка сообщает, что ссылка появится позже.

## Подготовка загрузки на GitHub

Подготовлены `.gitignore`, `.gitattributes`, зависимости, русская документация, шаблон сообщения об ошибке и автоматические проверки. `.gitignore` не удаляет файлы с диска.

В корне проекта выполните:

```powershell
git init -b main
git add .
git status --short
git commit -m "Подготовка NERKN"
```

Затем создайте пустой репозиторий на GitHub, добавьте его адрес как `origin` и отправьте ветку `main`. В этой задаче удалённый репозиторий не создаётся и публикация не выполняется.

Перед отправкой посмотрите `git status`: там не должно быть личных списков, конфигурации, архивов и результатов сборки. История старых версий не удаляется и при необходимости может храниться отдельно.
